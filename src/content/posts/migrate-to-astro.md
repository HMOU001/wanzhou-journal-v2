周六早上九点，我关掉了 WordPress 后台的最后一个标签页。这个决定酝酿了半年，执行只用了两天。周日晚上十一点，新站上线，构建时间 41 秒，首页体积 86 KB。

## 为什么搬走

旧站不是不能用，是每一处都要妥协。主题改一行 CSS 要穿过三层定制器；想给文章加一种「页边注」排版，插件市场里找不到，自己写又要和主题的模板层级搏斗。写作本身是愉快的，维护写作环境不是。

压垮它的最后一根稻草是一次例行更新：某个缓存插件升级后，全站文章的代码块样式集体失效。我花了两个小时排查，最后发现是它把 `pre` 标签的类名重写了一遍。那天晚上我决定，这个站的一砖一瓦，我要自己能看懂。

## 搬家清单

实际的工作量集中在三件事上：

1. **内容导出**：WordPress 的 XML 导出转 Markdown，用了一个现成的脚本，又手改了 frontmatter 的映射。三百篇文章里有两百八十多篇一次通过，剩下的多是早年从别的平台迁来时留下的格式残渣。
2. **URL 不搬家**：旧链接全部保留原路径，这是底线。搜索引擎的收录、别人文章里的引用，都不能断。Astro 的静态路由让这件事很直白。
3. **设计重做**：没有套主题。杂志式的排版是手写的，规矩线、期号、首字下沉，都是 CSS 里最朴素的写法。

<p class="marginnote">顺带一提：迁移过程中删掉了一百多篇 2019 年以前的短帖。它们更像当时的碎碎念，不像文章。刊物要有编辑，编辑要舍得删。</p>

## 两天之后

现在的写作流是：VS Code 里写 Markdown，git push，构建部署自动完成。没有后台，没有插件更新提醒，没有数据库备份焦虑。

> 工具的最好状态，是你忘记它的存在，只记得自己要写什么。

如果说有什么遗憾，是评论功能暂时没有搬过来。静态站的评论方案都不那么干净，我还在想这件事值不值得做。在那之前，邮件永远有效。
